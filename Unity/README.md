# SLOP CITY — Unity game project

Download the compiled **Apple Silicon macOS application** from the [private GitHub release](https://github.com/hollingsworthd/slop-city/releases/tag/v0.1.0). After rebuilding locally, it is at `Builds/macOS/SLOP CITY.app`. Double-click the app, then choose **Play** to enter Daniel's lounge. Running this standalone build does not require Unity Editor, Unity Hub, or a Unity license.

Git excludes compiled executables and editor caches. Use the release asset `SlopCity-macOS-AppleSilicon.zip` to play without rebuilding.

To edit or rebuild, open this folder as a project in **Unity 6.3 LTS 6000.3.26f1**. The project uses the Built-In Render Pipeline, legacy Input Manager, and Unity UI. iOS, Android, other desktop platforms, and consoles are future targets for this shared project.

## Current game

Daniel begins seated on his comfortable couch in first person. The view is clear: the headset equipment remains in the model, while its renderers and curved visor overlays are hidden from the local player. The loft includes the Machine Publishers TV, Hood Rich Records props, car keys, sauce packets, and a coding laptop.

The local loop is: get up, inspect the broadcast, return to the couch. Play/pause/restart/quit menus are included. This is a small playable lounge, not the complete online world; multiplayer networking and the earlier browser game are still separate.

## Rebuild for Mac

1. Sign into Unity Hub and activate your Unity license. Review and accept Unity's terms yourself if prompted.
2. Open this `Unity` folder with **6000.3.26f1**.
3. Choose **SLOP CITY → Build Mac Apple Silicon**. The scene is generated, validated, reopened, and compiled using the Mono scripting backend.
4. Run `Builds/macOS/SLOP CITY.app` after the build succeeds.

Alternatively run `BuildMac.command`. Set the `UNITY_EDITOR` environment variable if your editor is in a different location. The script uses the workspace editor by default. Build and scene validation receipts are in `Builds/Reports`; logs are in `Builds/Logs`.

The Apple Silicon Mac build compiled with zero build errors or warnings and passed scene validation. Live checks observed launch, Play, standing, movement/look, couch respawn, pause, the broadcast source card, clear first-person view, and corrected screen emission. See `Builds/Reports/mac-smoke-check.json` for the exact scope and remaining checks. Mobile and console builds are not yet available.

Command-line entry points:

- `SlopCity.Editor.SlopCityBatchBuild.BatchValidation`
- `SlopCity.Editor.SlopCityBatchBuild.BuildMacAppleSilicon`

Both use `-batchmode -quit -buildTarget StandaloneOSX -projectPath <this-folder>`. The build output is constrained to this project's `Builds` directory. Interactive rebuilding prompts before replacing generated scene work. Save manual scene edits under a different filename.

## Controls

| Input | Action |
| --- | --- |
| Play / Resume | Begin or continue the lounge |
| Mouse | Look around |
| WASD / arrow keys | Walk while standing |
| E | Stand up, sit down near the couch, or inspect a nearby TV/radio |
| R | Return to the couch |
| Esc | Pause or resume and release/capture the pointer |
| Restart | Reset the three local objectives |
| Quit | Close the application |

Inspecting a TV or radio displays an in-game source card. Opening its TikTok source requires clicking the source button. Videos and commercial tracks are not downloaded or bundled.

Touch controls automatically appear on mobile: a left joystick, right look area, and interact/respawn/pause buttons. The `SlopCityPlayerInput.forceTouchControlsForTesting` option exposes them in the editor for development. They still need real-device tests before mobile release. Stereo XR and tracked controllers are not implemented.

## Blender and source assets

`Assets/Art/SlopCity_Lounge.fbx` is generated by `../scripts/build_scene.py`. Use one Blender unit per metre and preserve the exact named objects:

| Object | Role |
| --- | --- |
| `Spawn_Daniel_Seated` | Seated camera eye point |
| `Spawn_Daniel_Stand` | Standing character feet point |
| `LookAt_Daniel_Seated` | Initial gaze target |
| `Headset_Daniel_Rig` | Wearable equipment hierarchy; hidden in first person |
| `Interact_TV` / `Interact_Radio` | Nearby source interactions |
| `Light_TableLamp` | Warm lamp light position |
| `Floor_Main` | Floor geometry and room extent |
| `COL_…` | Static collision geometry |
| `SC_Couch…` | Couch geometry with decorative seams excluded from collisions |

Unity converts the FBX axes. Do not manually swap marker coordinates or apply a 0.01 root scale. The scene builder creates matching base-colour and emissive materials, lighting, colliders, and the player. Blender's procedural fabric textures are not baked; the Blender render remains the visual reference.

The standing capsule is 1.72 m tall with a 0.22 m radius, and the standing eye is 1.62 m above the feet. The capsule is disabled while seated. Scene validation checks standing clearance before building.

## Verification before release

Build validation checks scene serialization, anchors, floor scale, required runtime references, camera and audio-listener count, collision geometry, standing clearance, and hidden headset renderers. A successful build receipt records compiler/build output; it does not establish interactive gameplay or device performance.

Test the compiled Mac app for start/resume/restart/quit, seated spawn, movement and collision, all objectives, source cards, pause/focus changes, resizing, and clean logs. The generated local app needs appropriate signing/notarization before broad Mac distribution. Mobile requires device testing, performance work, platform modules, and store-specific signing.

See `PLATFORM_ROADMAP.md` for the staged platform plan.
